## 2. 建议 preflight 顺序及验收件

### P0：冻结合同与配置

先选 GE/GEM、当前敌人 p/v 是否有噪声/延迟、中央更新频率及障碍融合规则，登记 oracle、上行与下行信息。固定共同 AW9/drag/积分、evader v2_fixed APF、normal capture、swept 碰撞、边界硬失败和 seed manifest。引用的 [Benchmark Contract](https://github.com/Jayyeah/cocap-voradj/blob/3038ef5cd728acdd302772ca08bf10060685af16/docs/paper/PAPER_ASSETS_20261015/PAPER_BENCHMARK_CONTRACT_DRAFT_ZH.md)仍是草案，不能把本报告建议写成已冻结评估器。

输出：版本化输入/输出合同、信息权限矩阵、模块/配置/调参预算与日志字段。无代码实现前不报告成功率。

### P1：固定快照分配验证

在小规模快照上验证人数需求、每机最多一任务、每槽位恰好一机、空闲/不可达处理、确定性 tie-break、切换滞回；用穷举小实例核验 min-cost-flow / LSAP 最优成本。这是约束求解核心的有意义验证。分别记录 A/B 两阶段与联合槽位的目标差异，不能要求二者结果一致。

默认四机、最少三机、均衡配额分别有配置；足够资源时不允许静默舍弃目标。AFRA 若另选，必须核验选项集、预算和经验库校准，避免仓库余量分配违约。

### P2：单目标几何与动力学

先无障碍，再有障碍与边界；分别三机、四机及更多人数、不同初始角度、较高速度目标。核查径向进入但角度失败、共线、重复角、额外邻机和转弯/刹车受限案例。与共同评估器逐事件对齐 normal capture，不用单机触碰/距离/凸包替代。

输出：动作合法性、真实 swept 碰撞、控制不可行原因、几何条件轨迹和按 seed 的失败分类。连续控制方案另先做原生论文小例，再建立适配差异表；不能跳过原生重建却标“忠实复现”。

### P3：多目标、释放与外生重复到达

从 4P1E1O、8P2E2O 到 12P3E3O；完整轨迹核验捕获移除、联盟释放、即时/周期重分配、跨组避碰和无目标部署。重复到达采用共享外生 arrival manifest；历史 B/C 的全队 Z 归零触发不适用于无 Z 的传统方法，不混合其历史统计。

输出：每目标等待接近、累计 normal capture、全波完成/删失、释放到再分配及再次接近时间。全局通知的新目标发现延迟按协议注明，不作为自主发现成绩。

### P4：规模与计算/通信

在同硬件、相同线程预算、计时边界和验证调参预算下，测 16/4/4、20/5/5、24/6/5 等合同规模；若用另一组 18/3/3、24/3/3，单独标清。报告分配、路径、控制/安全检查与整队 wall-clock 的 median/p95/p99、超 0.5 s 次数、重分配切换、上下行字节及地图增量；同时列 CoCap 整队推理，不能只比一次局部 QP 与单机策略。

## 3. 指标与解释规则

主指标：全目标 normal-capture success、完成时间、累计捕获和碰撞/边界事件。stationary fallback 单独列。完成时间保留失败/删失，报告成功数与删失原因，沿合同考虑累计发生率/RMST，不只平均成功局。人数使用、到达同步、空闲比例、联盟切换和最大目标等待可解释资源组织效率。

全目标捕获后的严格 CE 有 700 步恢复窗口，要求人数阈值及 CE_RMS≤0.05、CE_max≤0.10 持续 30 步；普通 horizon 3000 决策步。若完整系统没有 CE 恢复模块，只能给 capture-only 结果，不能悄悄改变完整任务成功定义。

允许全局传统基线表现更好。信息特权是显式实验变量，不是性能失败的借口；局部 CoCap 与 GE/GEM 的差异要同时讨论目标信息、地图、计算和通信。本文没有结果支持“CoCap 一定更快/更安全”。

## 4. 阶段停止与继续条件

若只剩距离跟踪但长期不能满足角终端、AW9 安全动作持续不可行、经验库迁移不校准或分配不断拆散联盟，应先诊断/修订模块，保留失败记录，不扩展到大批量正式跑。若小规模约束、几何、碰撞和生命周期验收通过，再决定正式复现投入。**本轮建议进入下一阶段 preflight，但当前提交只包含可审查的研究与设计成果。**
