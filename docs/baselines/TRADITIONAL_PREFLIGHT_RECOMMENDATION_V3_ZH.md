# V3 传统基线选型与下一阶段 preflight 合同

日期：2026-10-17。本文是下一阶段的可执行验收设计，**本轮没有启动下列实现、测试或训练**。

## 1. 三条路线与 GO 判断

| 路线 | 采用内容 | 任务/信息定位 | 决策及工程难度 |
|---|---|---|---|
| H-G1 | TR-11 Dynamic Robust Pursuit，Rao 等，JAS 13(4):989–991，2026；[DOI](https://doi.org/10.1109/JAS.2025.125684) | 多目标分组 + f-gon slot auction + C3AVC/CLF-CBF；全局目标/地图/队伍信息 | **CONDITIONAL_GO**，高；完整论文传统法只做一个时首选 |
| H-G2 | TR-13 CEO-DMPC，Chen 等，RA-L 9(3):2064–2071，2024；[DOI](https://doi.org/10.1109/LRA.2024.3349977) | circular patrol→检测→MILP 分组/slot→分布式 MPC；全实时追捕者通信 | **CONDITIONAL_GO**，高至很高；H-G1 不适配时的备选 |
| H-L | 年龄持续搜索 + GRAPE §V min-requirement coalition + 几何槽位/角间隔 + AW9 短预测 + release/search | 本机发现和实际邻居消息形成任务集；动态多轮服务；项目组合 | **CONDITIONAL_GO**，中至高；最贴近 CoCap 问题，推荐优先做局部组合 preflight |
| H-S | TR-05 扩展：相同搜索/执行/生命周期，替换为局部贪心三人承诺招募 | 透明辅助对照与联盟层消融 | **GO（可进入后续开发）**，中；不是完整已发表方法，也不是已完成系统 |

推荐没有变成“只选容易跑的开源算法”：TR-11 仍是强论文比较的首位，允许在信息特权下优于 CoCap。新增 H-L 回答此前完整论文都没有覆盖好的局部持续服务问题；不拿 H-S 代替 H-G。

最新 CFG-BAP 2026 等最低人数方法列为补全文后备；C* TRO 2026、LS-MCPP TRO 2025、Multi-CAP 和 HEDAC 分别作为搜索层升级/全局覆盖候选。它们不能解决“哪篇完整围捕论文可直接替换 CoCap”的全部问题。

## 2. 只有一个工程名额时如何选择

如果论文只能增加一个**有明确完整论文出处的传统围捕 baseline**，选择 H-G1。理由是全文/补充公式可获得、多目标多人分组与几何控制更完整；主缺口是官方实现、原生动力学到 AW9、速度差、normal capture 与生命周期。

如果资源只允许构建一个**场景匹配的非 RL 系统**，先验证 H-L。GRAPE 提供有理论来源的最低人数任务组织，SPACE 提供实际动态任务框架参考；搜索、会合、三机几何捕获、AW9 与释放均作为独立可验模块。这样可以回答 CoCap 在自主发现和持续任务循环中的价值，但论文必须称它为 literature-informed hierarchical baseline，而不能写“复现了 GRAPE 围捕算法”。

成本排序是定性工程判断，不是实测工时：小型 GRAPE allocator < H-S 闭环 < H-L 闭环 < 完整 H-G1 AW9 复现 ≲ H-G2。取决于要求复现原文证明/实验的深度，H-L 若追求严格分布式动态保证也可能超过 H-G1。

## 3. Preflight P0：冻结接口与信息条件

在原生 baseline 开发前形成一个所有方法共同的合同与不可变 seed/arrival manifest，列清：

1. AW9 动作表、drag、积分顺序、子步、实体尺寸和最大速度；不改目标 APF 行为。
2. normal / fallback / target collision / pursuer loss 的独立事件；normal 不加 hold。
3. 初始未知目标 ID/数量是否允许获知；本机 token、邻居 ID/位置、障碍图、记忆字段与追踪估计来源。
4. 通信图、消息每步次数/最大字节、TTL、序列化顺序、延迟、partition/地图大小与丢包机制。若与 CoCap 不同，则报告 local-with-extra-messaging，而非直接 matched-local。
5. 捕获事件给谁、何时给；若全队广播，所有方法一视同仁。没有阶段反馈时，不允许读取隐藏剩余目标数来切换 CE。
6. 一次决策的整队 wall-clock 截止与 solver/多轮消息预算；超时动作、不可行退化策略必须事先固定。
7. 单波与新共同重复到达协议分开。旧 PERSIST-B/C 的全队 Z 归零触发不复用给无 Z 系统。

验收物是解析后的合同和观测/消息字段表，而非一张架构图。方案值暂定不构成论文冻结事实。

## 4. Preflight P1：独立模块验证

| 模块 | 有意义的最小案例 | 通过要求 / 停止与修正理由 |
|---|---|---|
| 最低人数 allocator | 冻结目标快照；12人3任务、4人1任务、资源不足、代价并列、一个新任务加入 | 可服务任务满足人数，机器人不重复承诺；资源不足时可解释地排队；辅助偏好满足原条件，真实效用与辅助效用分别记录 |
| 消息与任务目录 | 两个机器人先后发现同目标；通信断开/恢复；延迟旧版本；任务过期 | 同一目标合并；无全目录/对象引用泄漏；过期 LOST 不伪作 CAPTURE；无无限同一步传播 |
| 持续搜索 | 无已知目标；障碍遮挡；扫过区域后出现新目标；搜索者中途加入/退出 | 能继续运动/重访并报告 revisit gap；CE 与发现率分别计算；不要求未知目标有上帝视角覆盖标签 |
| 三机几何 | 3/1 与4/1，目标静止/缓慢/原 APF；同侧初始；目标近障碍/边界 | 以原 normal 判据捕获；记录每步半径/最大gap/gap比和 infeasible；不能把稳定跟踪当通过 |
| AW9/安全适配 | 必须转向/减速绕障；近碰、邻居迎面；全部候选动作预测不安全 | 使用完全相同物理与 swept；动作合法；不可行保留失败事件；不通过则调整参考/预测，不改捕获或碰撞合同 |
| 释放闭环 | 捕获目标1后目标2仍未服务；最后一次捕获后再加入新目标；队员损失 | coalition 及时释放、无僵尸任务、无漏掉等待目标；记录 release→search/下一联盟延迟 |

不要求这些小例证明全局安全/捕获收敛。它们用于发现接口错误与明显不可实施性；通过后才有理由扩大场景。若原 APF 速度差导致持续不可达，保留该失败，区分动力学不适配与算法实现错误。

## 5. Preflight P2：H-G1 的论文身份与适配检查

先按论文自己的原生模型重建最小例：A* 距离、modified K-means 分组、polygon slot auction、C3AVC、安全/CLF-CBF 求解；固定小规模已知目标场景，核对分组/槽位/约束残差与求解状态。现有 SDQP 是独立严格凸 QP 组件；原文 LP 使用 Mosek，替换 solver 要记录等价性和残差，不能声称已取得完整官方代码。

然后以同一环境的 AW9 做适配，明确哪些连续控制/安全性质不再保证。将下面版本分开命名：

- `TR11-Native`：论文原生语义，仅用于复现检查，不能和 CoCap 主表混比。
- `TR11-AW9-Global`：共同运动学/normal/swept，全局信息，Privileged Comparator。
- `TR11-AW9-Global+SearchLifecycle`：额外加持续搜索和释放的组合扩展，分别报告新增模块，不能写成论文原有能力。

若 H-G1 在 AW9 单目标围捕阶段已明显不适配，先定位几何参考、速度差、求解约束和量化损失；仍无合理修正时再转 H-G2，而不是降低对手速度。H-G2 的全通信和 soft collision objective 也不能被“distributed MPC”标题隐藏。

## 6. Preflight P3：共同场景与消融矩阵

先运行小规模验证再扩大到 12/3/3；所有参数只在 validation seeds 上调节，测试 seeds 固定、不按测试结果回调。参数预算包括搜索权重/周期、追踪失效时间、切换滞回、资源保留人数、ring radius、参考增益、预测步长与 solver 时限。对传统方法给予合理模块和调参预算，CoCap checkpoint 及基准合同固定。

| 比较 | 要回答的问题 |
|---|---|
| H-G1 vs CoCap（分表） | 全局信息与显式分组/几何的强比较；只报告条件差异后的结果，不解释为信息公平因果优劣 |
| H-L vs CoCap（先审计信息） | 未知目标发现、最大等待、累计捕获、释放重搜、尺度变化及消息成本 |
| H-L vs H-S | 同一低层/搜索/生命周期下，GRAPE 最低人数组织是否优于贪心招募 |
| H-L persistent search vs static deployment | 搜索重访设计的贡献；静态版仅作为消融，不能取代合理主基线 |
| H-L one-step vs two-step AW9 | 执行可行性与计算预算之间的取舍 |
| H-L 限定消息 vs 更多消息 | 通信贡献；不同预算单列标签，不混为 matched |

指标至少包含：normal success、capture completion、每目标发现/首次接近时间、最大等待、按波累计捕获、recruit/会合时间、release→search、CE recovery、碰撞类型/人数、CPU p50/p95/p99、deadline miss、消息/字节、allocator 重求解/切换数、不可行比例。失败/删失保留在分母，不只统计成功局耗时。16/20/24 等规模实验按同合同分开报告，不编造泛化结果。

## 7. 主要风险与决策升级条件

| 风险 | 为什么实质影响结果 | 下一阶段的处理 |
|---|---|---|
| 目标3.5、追捕者3 m/s，且转向有限 | 原生全向控制证明可能不再适用；仅朝目标追会失败 | 先验证会合/侧向包夹与 AW9；明确失败场景，不作必捕获承诺 |
| GRAPE 全任务偏好/partition 与本地未知任务不一致 | 原证明在每机任务集不同、代价动态变化时未直接覆盖 | 冻结快照先验，再用 epoch 与任务发现扩展；不声称继承理论 |
| 消息传播和 live Task 对象 | 看似局部的代码可隐含全局目标 ID/最新位置/完成事件 | DTO、序列化与字段审计；带宽/记忆另列 |
| 三人分配但不同步到位 | 组织成功并不等于几何可捕获；队伍可能被反复拆走 | 人数承诺、会合、切换滞回及几何不可达反馈 |
| 搜索与 CE 的目标不同 | 持续巡逻未必满足严格静态 CE；无目标 oracle 会泄漏任务阶段 | 明确阶段反馈，分别报发现/CE；保留同合同对照 |
| 完整强方法无源码 | 公式可以重建，但参数、solver 和更新细节有风险 | 原生小例→残差/事件审计→AW9；把偏离原文的选择版本化 |

H-L 从 CONDITIONAL_GO 升为 GO 的条件是 P0 合同明确、P1 小例无信息泄漏/人数错误、至少完成合理 AW9 三机围捕与捕获后重启。H-G1 则还需原生公式重建可核和 AW9 适配足够可行。任何一项通过都不代表正式性能已经优于或低于 CoCap。

本轮建议是**值得进入 preflight**。实施与运行需在下一项工作中按上述合同展开；本轮没有隐式开始它们。
