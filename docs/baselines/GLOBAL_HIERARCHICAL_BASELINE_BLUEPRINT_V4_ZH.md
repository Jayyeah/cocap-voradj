# G-CAP：全局敌人信息下的集中式传统分层方案

日期：2026-10-17。身份：TR-15，**项目定义、文献支撑的传统组合系统，DESIGN_ONLY**。不是 TR-11、CEO-DMPC 或 AFRA 的官方实现。以下公式除明确引用原文者外均是拟议接口/目标函数。

## 1. 接口和整体闭环

```mermaid
flowchart LR
  S[全队状态 + 当前全局敌人] --> T[活动任务表与时间戳]
  T --> Q[人数配额与任务可行性]
  Q --> A[集中分组 / 几何槽位指派]
  A --> G[环形参考与路径]
  G --> U[AW9 预测与全队冲突检查]
  U --> E[同一 CoCap 环境]
  E -->|正常捕获 / 目标移除| R[释放联盟与事件重分配]
  R --> T
  T -->|无目标| D[监测 / 部署 / CE 恢复]
```

分配器输入活动机器人状态、当前敌人状态、允许的障碍信息及上一周期承诺；输出 `target_id, slot_id, quota, plan_epoch`。执行器只输出合法 AW9 动作。捕获和移除由共同评估器决定，不由本方法的“接近成功”阈值代替。任务 ID 不复用；记录分配时刻、首次进入 8 m、围捕、释放和再次接单时刻。

**GE** 允许当前敌人位置和速度全局获取；障碍来自感知融合图。未知区域的 A* 若作乐观自由空间，需要记录未知比例，并靠本地避障/更新重规划。**GEM** 可读完整障碍图，另表报告。都不读取未来目标动作。中央节点在同一时间戳快照求解，广播带版本的承诺，避免机器人混用不同周期的槽位。

## 2. 第一层：任务状态与估计

| 方法 | 输入/输出 | 采用条件与限制 |
|---|---|---|
| 当前真值 p/v oracle（GE 默认） | 所有活动敌人当前 p/v → 任务表 | 特权比较；不能同时声称解决局部发现 |
| 全局位置 + α–β/KF | 带噪/延迟位置 → 估计 p/v、时间戳 | 估计误差应计入预测；不能读取未来真实轨迹校正 |
| 集中融合局部轨迹 | 感知报告 → 统一轨迹 | 可另做 centralized-local-sensing 变体；不是本轮全局敌人主配置 |

GE 主结果不需要无目标探索来寻找已知敌人。无目标转 DEPLOY/MONITOR；若报告原合同 strict CE，必须实现或复用已冻结的部署接口并给所有方法同等机会。静态 CE 恢复与持续搜索效率是不同指标。[合同 §2.3](https://github.com/Jayyeah/cocap-voradj/blob/3038ef5cd728acdd302772ca08bf10060685af16/docs/paper/PAPER_ASSETS_20261015/PAPER_BENCHMARK_CONTRACT_DRAFT_ZH.md)。

## 3. 第二层：人数配额、资源不足与优先级

约束为每个服务目标 `q_j ≥ 3`，总需求 `S=Σq_j ≤ N_active`。优先预试 **q=4**（主规模恰好 4/1、8/2、12/3）及均衡人数 `floor(N/M)`/`ceil(N/M)`。把“每目标至少三机”写成“恰好三机”会无谓削弱传统方法。主规模有足够人数时，先保证所有目标被服务；空闲机器人可部署、接替或在验证通过后增援。

可替换算法：

1. **固定/均衡配额**：最透明、无经验库；目标变动后重新平衡，加入切换滞回，避免高频拆联盟。
2. **小规模配额枚举 + 指派**：枚举预算允许的 `q_j∈{3,4,…,q_max}`，比较运输、角度误差、等待和切换成本；组合数随目标数增加，不能宣称总成本仅是一次线性指派。
3. **AFRA 经验库 + MCKP-DP**：原文 `K_j={0,4,…,15}`，最大化 `Σp_j(q_j)`，时间 `O(M N |K|)`，内存 `O(MN)`。它只输出每目标人数，**并不完成哪台机器人去哪个目标、槽位与几何执行**；后续仍需第三、四层。[AFRA pp.10–11 §4.2，含式(15)–(20)](https://mdpi-res.com/d_attachment/drones/drones-10-00406/article_deploy/drones-10-00406.pdf)。
4. **CP-SAT/MILP 联合激活**：当 `N<3M`，设 `y_j∈{0,1}`，`3y_j≤Σ_i x_ij≤q_max y_j`，加入等待年龄或期限目标。此时完整任务选择不再是单纯固定需求运输问题；必须报告未服务任务、右删失等待，不能把跳过难目标当作全部完成。

AFRA 原经验库不适用于 CoCap：需在相同 AW9、normal capture、地图/初始化分布和控制器下重建；只用验证种子，计入离线 Monte Carlo 预算。相同敌人速度上限下，单靠速度比对所有目标给出相同描述，未必能表达障碍/距离/初始角度的难度。改用情境特征属于扩展，不得称原算法已做到。

## 4. 第三层：集中式分组与槽位指派

### 4.1 两阶段方案 A：最接近 CEO-DMPC 的分配结构

第一阶段求解（用本项目代价记号）：

`min Σ_i Σ_j c_ij x_ij`

`Σ_j x_ij ≤ 1；Σ_i x_ij = q_j；x_ij∈{0,1}`。

这是固定需求、可加线性代价的运输/最小费用流结构。源→机器人容量 1，机器人→目标容量 1、费用 `c_ij`，目标→汇容量和需求 `q_j`，固定总流 `S`；机器人多于需求时允许闲置。整数容量保证整数流，**该特例无需把一般 MRTA 的 NP-hard 标签套过来**。TR-13 原式(7)用距离、固定 `n_req`，原文建模为 MILP；我们使用流结构求同一形式的固定需求分组，是实现选择。[作者 PDF p.3 §IV](https://april.zju.edu.cn/wp-content/papercite-data/pdf/chen2024adp.pdf)。

第二阶段在每组内求机器人与 `q_j` 个槽位一对一指派，代价 `d_i,jk`，对应原式(8)。可用 [SciPy `linear_sum_assignment`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html)；其实际算法为 modified Jonker–Volgenant，不将库实现误称为 Hungarian。正方形槽位指派常用复杂度量级 `O(q_j³)`，具体矩形实现/常数须实测。

### 4.2 一阶段方案 B：联合全局槽位指派

生成所有目标的全部槽位 `s=(j,k)`，构建 `N×S` 代价矩阵，`N≥S` 时一次矩形线性指派，令每槽位由一台不同机器人承担。每目标槽位齐备，因此最低人数不会被无承诺拆散。**B 的目标是总代价到槽位最小，A 先最小化到目标再组内最小化到槽位，二者一般不等价。** 推荐以 B 为 G-CAP 简洁实现、A 为论文分配结构对照；在验证集定版后冻结。

成本可取 `d_path/v_ref + w_heading e_heading + w_switch 1(change) + w_age age_term`；不同项归一化，权重、A* 分辨率和不可达边处理写入配置。欧氏距离可作无地图备选，A* 借鉴 TR-11 p.990，但全图 A* 只能用于 GEM。障碍使某槽位不可达时，禁用边；若无法覆盖全部槽位，应返回明确不可行，换相位/半径或重新配额，而非强行塞入一个大有限代价并称成功。

工具备选：[OR-Tools 最小费用流](https://developers.google.com/optimization/flow/assignment_min_cost_flow)、SciPy LSAP、OR-Tools CP-SAT。都只是优化组件，没有自动实现围捕或 AW9 安全。

## 5. 第四层：几何参考、围捕反馈与路径

目标中心槽位：

`g_jk = p_hat_j + ρ_j [cos(φ_j+2πk/q_j), sin(φ_j+2πk/q_j)]`。

正多边形的物理意义是同时限制径向距离和角度不均；原生构造见 TR-13 p.4 式(8)前定义、TR-11 p.990。CoCap 正常捕获要求中心距不超过 8 m、最大角间隙不超过 π 且最大/最小间隙比不超过 3。选择 `ρ<8` 并留跟踪余量；理想等角 `q≥3` 满足角条件，但**跟踪动态、额外邻机、碰撞、边界和最小间隙仍由真实评估器判定**。不能只统计分组内距离就宣告捕获。

可分别替换：

| 子层 | 简洁方案 | 强方案/文献 | 缺口 |
|---|---|---|---|
| 相位/半径 | 小网格候选，按总到达代价及可行性选 | 联合优化，或 TR-11 的多边形槽位 | 不可行圆环不能逐点裁剪后仍声称保持角几何 |
| 槽位承诺 | 任务周期内保序，切换罚项与最短承诺时间 | 原生拍卖（TR-11）；原生位置 MILP（TR-13） | 中央版本不需要假装执行分布式拍卖 |
| 参考反馈 | 径向误差 + 槽位误差 + 最大角间隙惩罚 | CEO-DMPC；C3AVC+CLF/CBF；RMPC 单目标模块 | 简洁控制器是项目实现；连续证明不能直接转移 |
| 障碍路径 | 已知/融合地图 A* + 在线重规划 | WHCA*；安全域内局部目标投影 | A* 位置路径没有 AW9 可执行性或 swept 安全保证 |
| 低复杂度控制参考 | APF 吸引/排斥 | AFRA 原式(2)、(5)–(7) | 普通 APF 可能局部极小；排斥不等于硬安全，不足以保证闭合围捕 |

建议代价中的角误差用环形排序后的间隙和共同捕获裕度，避免只“贴近目标”而所有追捕者挤在一侧。两目标相近时两个环可能重叠；需要跨联盟冲突检查与相位调整。原文没有解决的接口明确列为项目扩展。

## 6. 第五层：CoCap AW9 执行与安全

直接使用共同环境的状态转移（含速度截断、drag 和积分次序），不手写近似模型替代事实源。0.5 s 一个决策、10 个 0.05 s 子步，`a∈{-0.4,0,0.4}`，`ω∈{-π/6,0,π/6}`，pursuer 最大速度 3 m/s，目标最大速度 3.5 m/s。禁止把连续速度指令瞬时旋转/量化后宣称继承收敛或安全证明。

首版可对每机器人 9 个动作前向预测；必要时两步共 81 序列，评分包括距离/角度误差、平滑与接近同步。中央协调采取固定或轮换优先级、轨迹预留和冲突重选，最后检查整队联合动作；不是枚举 `9^N` 联合动作。目标预测用当前 p/v 和明确的不确定裕度，不使用未来真实 APF 动作。

所有预测都应检查子步与同步 swept 碰撞；共同评估器负责最终事件。优先级预测可能失败、转弯限制可能使安全动作集为空；记录原因和后备规则。没有可行动作就报告不可行，不能通过边界反弹、穿障或瞬移“恢复”。这一层不享有连续 CBF 的自动硬安全保证。

## 7. 第六层：捕获、释放与再分配

`ASSIGNED → RENDEZVOUS → ENCIRCLE → RELEASE → REASSIGN`；另外有 `INFEASIBLE/TIMEOUT` 和 `IDLE_DEPLOY`。

- 捕获以共同 normal-capture 事件为准，目标立即从任务表移除，释放该联盟。下一决策快照对剩余目标重新求解；若无剩余目标，执行监测/部署或合同 CE 恢复。
- 新目标到达由外生协议加入全局任务表，可触发重分配；不读取尚未出现的目标。记录释放到再接单、再接单到接近的时间。
- 除完成/新到达等硬事件外，周期重求解使用最短承诺时间、改善阈值与切换罚项，避免把会合中的几何结构每步拆散。
- 论文能力分别标注：TR-11 有动态分配；TR-13 有在线分组/预测；AFRA 有阶段威胁和预算重分配。三者均不能据现有证据写成已验证“捕获移除—自由联盟—新目标到达—再次执行”的完整 CoCap 生命周期。

## 8. 计算与通信的可测成本

状态/任务表存储 `O(N+M)`；分组代价矩阵 `O(NM)`，全局槽位矩阵 `O(NS)`；方阵 LSAP 常见量级 `O(max(N,S)³)`，并记录实际矩形实现耗时；最小费用流按求解器、顶点/边数报告，不以一个通用多项式口号替代实测。A* 每次在有限图上通常为 `O((V+E)log V)`，但次数和缓存命中必须另外报告。配额枚举、相位网格、滚动预测的乘数都要计入总耗时。

每次中央更新至少汇集 `O(N+M)` 个状态记录、下发 `O(N)` 个指派/动作记录，若传地图或预测轨迹则更大。假设 enemy oracle 直接进入中央，也要单列 oracle 信息量；不能把模拟器共享内存的零网络耗时写成真实零通信。比较分层 CPU、整队决策 wall-clock、最坏/p95 延迟、重求解次数、消息频率与字节数，不预设传统方法一定比 CoCap 慢。
